## 1. Javascript의 this 키워드도 대체로 자기 자신(객체)를 가리킨다

보통 **Java**같은 객체지향언어에서 ```this```가 가리키는 대상은 ```this``` 를 선언한 해당 메소드를 수행중인 자기 자신(객체)이다. **Javascript**에서 ```this``` 는 이와 비슷한 역할을 한다. 우선, 기본적으로 **Javacript**의 ```this```키워드는 다른 객체지향언어와 마찬가지로 ```this```가 선언된 메소드를 수행중인 객체를 가리킨다.

```js
function person() {
  this.name = "강아무개"; //person클래스의 생성자 메소드에서 선언. 즉, 생성자를 통해 생성할 person 객체를 가리킨다.
}

//ES6 문법에서 등장한 class 선언 문법
class person {
  constructor() {
    this.name = "강아무개";//마찬가지로 this는 새로 생성할 person 객체를 가리킨다.
  }
}
```

## 2. Javascript의 this 키워드가 특별한 점

그러나, **Javascript**에서의 ```this``` 키워드는 객체의 메소드가 아닌곳에서 선언될 수가 있다. 대표적으로, 메소드가 아닌 함수에서 선언된 ```this```키워드나, 전역에서 선언된 ```this```키워드를 생각할 수가 있다. **Javascript**는 객체 메소드에 대한 함수의 동적인 할당이 가능하고 메소드가 아닌 함수가 ```this```키워드를 갖는다는 것은 해당 함수가 메소드로 할당되어서 **invoke**하게되는 객체가 무엇인가에 따라 ```this```가 가리키는 대상이 바뀔 수 있다는 것이다. 이는 **Javascript**과 타 언어간의 가장 큰 차이점으로 ```this```가 가리키는 대상(함수 컨텍스트)가 타 언어 처럼 선언될 때 결정되는 것이 아닌 호출될 때 결정된다.

> this는 실행컨텍스트를 가르킨다

### 2.1. 함수 컨텍스트에서의 this 키워드

어떤 함수 내에서 선언된 ```this```의 값은 그 함수가 어떤 객체를 통해 **invoke**되어지는가에 따라 결정된다.

#### 2.1.1. 함수가 객체를 통하지 않고 단순 호출되어질 때

함수는 수행하는 객체가 따로 없다. 즉, ```this```는 ```undefined``` 이어야 하나 **Javascript**엔진은 ```null```또는 ```undefined```인 ```this```에 대해 자동으로 전역객체로 변환해준다. 함수를 전역 객체의 메소드로 보는 시각으로보면 맞는 말이다.

__따라서, ```this```가 가리키는 대상은 전역객체가 된다.__

**Javascript**의 전역객체는 브라우저 환경에선 **window**이며 **Node.js**에서는 **global**이다.

그러나 ```use strict```를 통한 엄격모드에서는 ```this```가 ```null```이거나 ```undefined```인 경우를 포함한 그 어떤 경우에도 자동으로 전역객체로 변환해주지 않는다. 이는 보다 안전한 **Javascript**를 위해 추가된 사항으로 웹 사이트에서 사용자가 임의로 작성한 함수가 전역객체를 참조 못하게하여 웹 사이트의 보안 구현을 좀더 용이하게 한다.

#### 2.1.2. 함수가 다른 객체의 메소드로 할당되어 사용될 때

함수는 어떤 객체의 메소드에 할당되어질 수 있고, 메소드 또한 다른 타입의 객체의 메소드로 할당되어 질 수 있다. 이는 메소드에 대한 참조를 사용자 코드에서 유지하고 새롭게 할당 및 변경이 가능한 **Javascript**의 특징이다.

**함수가 객체의 메소드로 할당되어 사용되어지면, ```this```는 그 객체를 가리키게 된다.**

```js
function getThis(){
    return this;
}

getThis();//Window

function person(){
    this.name="강아무개";
    this.do = getThis;
}

person().do();//{name: '강아무개', do: ƒ}
```
